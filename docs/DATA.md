# Data

## Sources

Two exports from a fictional e-commerce company, committed in `data/raw/` and reproducible with
`python scripts/generate_sample_data.py` (fixed seed 42; output is byte-identical every time).

### `customers.jsonl` — CRM export (JSON Lines, nested)

```json
{"customer_id": "C00002", "name": "Rohan Singh", "email": "rohan.singh2@example.com",
 "signup_date": "10/27/2024", "address": {"city": "Seattle", "country": "us"},
 "updated_at": "2025-07-01T09:00:00"}
```

| Field | Meaning | Target column |
|---|---|---|
| `customer_id` | business key | `customers.customer_id` (PK) |
| `name`, `email` | contact data | `name`, `email` |
| `signup_date` | date in one of three formats | `signup_date` (ISO date) |
| `address.city`, `address.country` | nested; country is free text | `city`, `country_code` (ISO 3166-1 alpha-2) |
| `updated_at` | when the CRM last changed the record | `source_updated_at` (version ordering) |

### `orders.csv` — order system export

```
order_id,customer_id,order_date,sku,quantity,unit_price,currency,status,updated_at
O000002,C00048,05/10/2026,SKU-029,1,221.51,USD,SHIPPED ,2026-05-11T07:00:00
```

One row per order line. `unit_price` is per unit, in `currency`. `updated_at` changes when the order's status
changes; the export re-emits the row.

`wrong_field_count(n!=9)`.

## Why each invalid record is handled the way it is

* **Rejected (`error`)** when loading would require inventing a value that matters: a key (cannot dedupe or
  join), a customer reference (breaks referential integrity), or any input to revenue (date, SKU, quantity,
  price, currency). Guessing these would silently corrupt totals.
* **Loaded with a flag (`warn`)** when the record is still valuable and only a descriptive field is bad.
  Rejecting a customer for a malformed email would also orphan all of that customer's orders.
* **Normalized silently but counted** when the value is unambiguous and only the spelling differs
  (`usa` → `US`, `$1,299.00` → 129900 cents).
* **Quarantined, never deleted.** Every rejected record is in the `quarantine` table with its raw text, source
  file and line, and all failing rules, so it can be fixed at the source and picked up by the next run.
